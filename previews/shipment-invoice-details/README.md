# Shipment Invoice Details and edit preview

Open `index.html` directly in a browser. This file is self-contained and can be downloaded/shared on its own. All actions use fictional in-memory data; there are no production connections or persistent writes.

Use the visible scenario and EN/EL selectors. Try Edit draft, Source changes, Finalized, Cancelled, Replacement form and Concurrent change. Loading, empty goods, load/save errors, overlap, incomplete draft and mixed currency are also included. URL example: `?state=edit&lang=el`.

The stacked-card direction follows the user's approved Q15 and the FRO-363 create design. New compositions and numbered business notes are marked in the preview. See `component-map.md` for source mapping and integration boundaries. Fonts/native select/date popups approximate the real portal.

The preview is ready for design review, not an approved Linear specification or production implementation. Concrete API contracts, review versioning/persistence, replacement integration and consumer tracing remain for the spec-check stage. No ticket has been created for this Details/edit work yet.

## Verification

Run `node build.cjs` after changing preview.js to embed it into index.html. The downloadable HTML has no dependency on preview.js. Run `node verify.cjs` with Playwright available, or set `PLAYWRIGHT_MODULE` to an installed Playwright module path. Headless Microsoft Edge is used. Verification covers 56 EN/EL desktop/400px scenario combinations and lifecycle/retention checks; results are in verification.json. desktop.png and mobile.png are regenerated by verification.

Printing/PDF/discount controls remain outside this preview. Allocation and Shipment navigation destinations are explicitly simulated boundaries of other UI tickets. Role selection is a design tool, not authorization implementation. Fixture number DEMO-INVOICE-0042 is never a production sequence value.
